# ジャンプ コレクション

週刊少年ジャンプ（1981〜2026年）、ジャンプコミックス、コミックスに挟み込まれていた冊子（コミックスニュース・ジャンパラ・ジャンコミスクープ）を全冊コンプリートするための、スマートフォン向け所持管理Webアプリです。
画面上部のタブでコレクションを切り替えます（横にスクロールできます）。
React + TypeScript + Vite + Tailwind CSS で作ったPWAです。

---

## セットアップ

必要なもの: Node.js 20以上（22推奨）

```bash
npm install
npm run dev        # 開発サーバー起動 → http://localhost:5173
```

スマホで確認したいとき: PCとスマホを同じWi-Fiにつなぎ、`npm run dev` を実行したときに表示される
`Network: http://192.168.x.x:5173` をスマホのブラウザで開いてください。

本番ビルド:

```bash
npm run build      # dist/ に出力
npm run preview    # ビルド結果をローカルで確認 → http://localhost:4173
```

`dist/` の中身は静的ファイルだけなので、GitHub Pages・Netlify・Vercel などにそのまま置けます
（`base: './'` にしてあるため、サブディレクトリに置いても動きます）。

### GitHub Pages で公開

`.github/workflows/deploy.yml` が入っています。`main` ブランチにpushすると、自動でビルドして公開されます。

1. GitHubのリポジトリで Settings → Pages → Build and deployment の Source を **GitHub Actions** にする
2. `main` にpushする（Actionsタブでビルドの進み具合を見られます）
3. `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けます。HTTPSなので、ホーム画面への追加（PWA）も使えます

### HTML 1ファイル版

```bash
npm run build:html   # → dist-html/index.html
```

CSS・JS・アイコンをすべて埋め込んだHTMLファイルが1つできます。ダブルクリックやスマホのファイルアプリで開くだけで動きます。
機能はPWA版と同じですが、Service Worker（オフラインキャッシュ・インストール）は付きません。
記録は開いたブラウザの localStorage に保存されます。同じファイルでも、開く場所（PC・スマホ・公開URL）が違えば記録も別になります。

### ホーム画面に追加（PWA）

PWA（ホーム画面への追加やオフライン動作）は **HTTPS** か **localhost** で開いたときだけ使えます。
スマホからLAN内のIPアドレスで開いた場合、画面は動きますがホーム画面アプリにはなりません。
GitHub Pages などに公開してから追加してください。

- iPhone: Safari の共有ボタン →「ホーム画面に追加」
- Android: Chrome のメニュー →「ホーム画面に追加」または「アプリをインストール」

## 使い方

| 操作 | 動作 |
|---|---|
| 号のタイルをタップ | 未確認 → **所持済み**（緑・○）|
| もう一度タップ | 所持済み → **未所持** |
| 長押し（約0.5秒） | **未確認**に戻す |
| ‹ ›／年のプルダウン | 年を切り替え（プルダウンには年ごとの所持数も表示）|
| すべて／所持済み／未所持／未確認 | 表示の絞り込み |
| 「○○年の刊行号データを編集」 | 合併号・号の追加や削除・確定（下記）|

### 3つの状態

- **未確認**（初期状態）: まだ調べていない号。未所持とはみなしません
- **所持済み**: 持っている号
- **未所持**: 持っていないことを確認した号

コンプリート率は「所持済み ÷ その年の刊行号の冊数」です。

## ジャンプコミックス

雑誌は「年 → 号」、コミックスは「作品 → 巻」で管理します。

- **作品を追加**: 作品名・巻数・状態（完結／連載中）・特別巻（例: 0巻、外伝）を入力して登録します
- **完結作品から選ぶ**: よく知られた完結作品（DRAGON BALL・SLAM DUNKなど42作品）を選んで、まとめて登録できます。
  巻数は一般に知られているJC通常版の最終巻数で、資料と照合していないため、**登録すると暫定になります**
- 作品一覧には作品ごとの所持率と「○ コンプ」を表示します。検索、並び替え（追加順・作品名順・所持率順）、
  絞り込み（すべて・未コンプ・コンプ済み）ができます
- 作品を開くと巻のグリッドが出ます。操作は雑誌と同じです（タップで所持済み⇄未所持、長押しで未確認）
- 連載中の作品は「＋ 新刊を追加」で1巻ずつ増やせます
- 「作品データを編集」で巻数などを直せます。出典を書けば確定にできます。巻数や特別巻を変えると、確定は外れて暫定に戻ります
- 作品を削除すると、その作品の所持記録も消えます。巻数を減らしただけなら記録は残ります

## 折込冊子（コミックスニュース・ジャンパラ・ジャンコミスクープ）

週刊少年ジャンプと同じく、号のタイルをタップしてチェックするだけで使えます。

| コレクション | 収録範囲（初期） |
|---|---|
| コミックスニュース | Vol.1〜260 |
| ジャンパラ | Vol.1〜195 |
| ジャンコミスクープ | Vol.1〜83 |

- 新しい号が出たら、一覧の下にある「＋ 新しい号を追加」を押します。1号ずつ増えます
- 追加しすぎた場合は、「Vol.○ を外す」で最後の号を外せます（所持記録は残ります）
- 号の範囲は `src/data/inserts.ts` の `defaultCount` で変えられます
- 所持記録のIDは `ins:コレクションID:Vol番号` の形式です（例: `ins:jancomi-scoop:83`）

## 刊行号データについて（重要）

**刊行号データ（どの号が実在するか）と所持記録（どの号を持っているか）は別々に管理しています。**

### 今の状態: 全年「暫定」

1981〜2026年の正確な刊行号一覧（合併号を含む）は、まだ裏付けの取れた資料がありません。
そのため同梱しているのは、**各年1〜52号を単号で並べた暫定の雛形だけ**です。

- 画面では「暫定」バッジと点線の枠で表示します
- 合併号や実際の冊数は反映していないので、冊数・コンプリート率も暫定値です
- 暫定データを「確定」として表示することはありません

### 実際の刊行号に合わせる方法

**A. アプリ内で編集する（端末ごと）**

1. 「○○年の刊行号データを編集」を開く
2. 合併号は「次と合併」（例: 3号で押すと「3・4号」になります）。間違えたら「分割」
3. 存在しない号は「削除」、足りない号は「号を追加」
4. 資料で全号を照合できたら、出典を書いて「この年を確定データにする」

- 編集した年は、出典を書いて確定するまで暫定のままです
- 合併や分割をすると、その号の所持記録は新しい号に引き継がれます
- 号を削除しても所持記録は消さずに残します（号を戻すと復活し、CSVにも書き出されます）
- 編集した内容はJSONバックアップに含まれます

**B. 確定データを同梱する（全端末共通）**

`src/data/confirmed/` に年ごとのJSONを置くと、ビルドしたときに取り込まれ、その年は「確定」になります。

```json
// src/data/confirmed/1985.json
{
  "year": 1985,
  "source": "国立国会図書館 所蔵目録で照合",
  "issues": [[1], [2], [3, 4], [5], [6]]
}
```

`issues` は1冊ごとの号数の配列で、合併号は `[3, 4]` のように書きます。
**裏付けの取れた年だけ**を置いてください。

### データの優先順位

アプリ内の編集 ＞ `src/data/confirmed/*.json`（確定） ＞ 暫定雛形

## 初期データ（src/data/seed.json）

記録がまったくない端末で初めて開いたときだけ、`src/data/seed.json` の記録が自動で読み込まれます（2026年11月3日に書き出したCSVの内容：雑誌の所持記録と合併号の編集、コミックス39作品）。すでに記録がある端末では自動では読み込みません。その場合は「データ」→「11月3日の記録を取り込む」を押すと、今の記録を残したまま統合されます。

作り直したいときは、アプリでCSVを書き出してから次を実行してください。

```bash
node scripts/csv-to-seed.mjs 書き出したファイル.csv
```

CSVには「完結／連載中」が含まれないため、連載中の作品名は `scripts/csv-to-seed.mjs` の `ONGOING_TITLES` で指定します（それ以外は完結になります）。

## データ保存

ブラウザの **localStorage** に自動で保存されます。ブラウザを閉じても、端末を再起動しても残ります。

| キー | 内容 |
|---|---|
| `jump-collection:ownership:v1` | 所持記録（号ID → 状態・更新日時）|
| `jump-collection:catalog-overrides:v1` | アプリ内で編集した刊行号データ |
| `jump-collection:comics-series:v1` | コミックスの作品登録（作品名・巻数など）|
| `jump-collection:inserts:v1` | 折込冊子の最新号（追加した号数）|
| `jump-collection:ui:year` | 最後に開いていた年 |

- 号IDは `年-号数` の形式です（例: `1985-12`、合併号は `1985-3-4`）
- コミックスの巻IDは `jc:作品ID:巻` の形式です（例: `jc:p-dragonball:12`、特別巻は `jc:s-xxxx:x:0巻`）
- 「未確認」の号は記録を持ちません（記録がない＝未確認）
- 各記録には `updatedAt`（更新日時）を付けています。将来、複数の端末で同期するときに新しいほうを採用するためです

**ご注意:** localStorage は「ブラウザ × 端末」ごとに別々です。iPhoneの Safari とホーム画面アプリ、
PCとスマホでは記録が共有されません。また、ブラウザのデータを消去すると記録も消えます。
定期的にバックアップしてください。

## バックアップと復元

右上の「バックアップ」から操作します。

| 形式 | 中身 | 用途 |
|---|---|---|
| **JSON** | 所持記録 ＋ 刊行号データの編集内容 ＋ コミックスの作品登録 ＋ 折込冊子の最新号 | 完全なバックアップ、機種変更 |
| **CSV** | 雑誌の全号とコミックスの全巻の一覧（種別・ID・年・作品名・号/巻・状態・暫定/確定・更新日時）| Excel や Numbers での閲覧・チェックリスト |

- **JSONから復元**: 所持記録と刊行号データの編集内容を、どちらも上書きします
- **CSVから取り込む**: 今の記録を消さずに統合します。所持記録に加えて、コミックスの作品（作品名・巻数）、合併号などの刊行号データ、折込冊子の号数も読み取ります。同じ号は新しく記録したほうを残します。CSVには「完結／連載中」が含まれないため、新しく追加された作品は「完結」になります（`issue_id` と `status` 列を使います。`status_ja` 列の「所持済み／未所持／未確認」でも読み込めます）
- CSVには、Excelで文字化けしないようにBOMを付けています

機種変更するときは、古い端末でJSONを書き出し → ファイルを新しい端末に送る → 「JSONから復元」の順に操作してください。

## 複数端末の同期（Firebase）

Googleアカウントでログインすると、スマホ・PCなど全端末で記録が自動的に同じになります。
`src/firebaseConfig.ts` が `null` のままなら同期機能は表示されず、これまでどおり端末内だけで動きます。

### 設定手順（最初に1回だけ）

1. https://console.firebase.google.com/ で「プロジェクトを追加」（例: `jump-collection`）。Googleアナリティクスはオフで大丈夫です
2. **Authentication** → 始める → ログイン方法で **Google** を有効にする
3. Authentication → 設定 → **承認済みドメイン** に `tetetepoke.github.io` を追加する（`localhost` は最初から入っています）
4. **Firestore Database** → データベースを作成 → ロケーションは `asia-northeast1`（東京）、本番モードで作成する
5. Firestore → **ルール** を次の内容にして「公開」を押す（自分のデータだけ読み書きできるようにします）
   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /users/{uid} {
         allow read, write: if request.auth != null && request.auth.uid == uid;
       }
     }
   }
   ```
6. プロジェクトの設定（歯車）→ マイアプリ → **ウェブ（</>）** でアプリを登録し、表示された `firebaseConfig` の値を `src/firebaseConfig.ts` の `null` の部分に貼り付ける
   ```ts
   } | null = {
     apiKey: '...',
     authDomain: '....firebaseapp.com',
     projectId: '...',
     appId: '...',
   }
   ```
7. GitHubにpushすると自動で公開されます。アプリの「データ」→「Googleでログインして同期」でログインします

### 仕組み

- Firestore の `users/{ユーザーID}` という1つのドキュメントに、所持記録・刊行号データ・作品登録・折込冊子の最新号をすべて保存します
- 変更は1件単位で書き込むので、2台で同時に操作しても、お互いの変更を消し合いません
- 端末内（localStorage）にも保存し続けるので、オフラインでも使えます。通信が戻ると自動で送信されます
- 初めてログインしたときは、その端末の記録とクラウドの記録をまとめます。同じ号に記録がある場合は、新しく記録したほうを採用します
- ログアウトしても、端末の記録は残ります
- `apiKey` などの値は公開しても問題ありません。データは上のルールで保護されます
- **ご注意:** Googleログインは、HTTPSの公開URLか localhost で開いたときだけ使えます。HTML1ファイル版をファイルとして直接開いた場合は使えません

## 別のサービスで同期する場合（Supabase など）

保存処理は `StorageAdapter` インターフェースにまとめてあります。

```
src/storage/
  adapter.ts                  # インターフェース（すべて Promise を返す）
  localStorageAdapter.ts      # 今使っている実装
  supabaseAdapter.example.ts  # Supabase 版の雛形（テーブル定義・実装例つき・未使用）
  index.ts                    # ここで使う実装を切り替える
```

同期に対応するときは、雛形を参考に `SupabaseAdapter` を作り、`src/storage/index.ts` の1行を差し替えるだけです。
画面側のコードは変更不要です。

## ディレクトリ構成

```
src/
  types.ts                 # 刊行号データ・所持記録の型
  data/
    catalog.ts             # 年の範囲・暫定雛形・有効なカタログの決定

    confirmed/             # 確定刊行号データ（年別JSON）
  storage/                 # 保存先の抽象化
  lib/backup.ts            # JSON/CSV の書き出し・復元
  hooks/useCollection.ts   # 状態管理・自動保存・集計
  components/              # 画面部品（年ナビ、統計、フィルタ、号グリッド、編集、バックアップ）
public/icons/              # PWAアイコン
```
